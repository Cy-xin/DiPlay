# DiPlay Geely 0.1.1：无线识别初始化修复

## 已确认的问题

Redmi K40（Android 13 / API 33）的只读诊断显示：

- 蓝牙权限已授予，iPhone 已绑定，并能发现其 iAP2 服务。
- RFCOMM 已成功连接，输入输出流及 iAP2 CSM 通道均已打开。
- 应用获取不到物理蓝牙地址，日志中本机蓝牙标识为空。
- 紧接着无线识别初始化抛出 IllegalArgumentException，尚未开始 MFi 握手、发送网络配置或进入 AirPlay。

根因是最小版创建 AirPlayConfig 时漏保留了原版的蓝牙标识回退，将 btMac 留空。
Iap2WirelessIdentification 要求六组十六进制字节的地址，因而在蓝牙连接已经成功之后拒绝该空值。
旧错误提示将包含 Bluetooth 的错误一概显示为蓝牙不可用，误导了排查。

## 修复

恢复原版行为：优先由控制器使用系统可读的真实蓝牙地址；系统隐藏地址时，使用持久化 AirPlay 身份派生的合法逻辑标识作为回退。
这不是声称读取到了物理地址，也不通过 Root、ADB 注入或修改系统设置取得地址。
生产配置统一在 receiverAirPlayConfig 中创建；将标识错误和通用蓝牙/RFCOMM 失败分开提示。

版本为 0.1.1-geely-minimal，versionCode 101。包名、签名方式和配置存储不变，可覆盖安装本次先前交付的 0.1.0，无需清空配置或删除配对。

## 验证与边界

新增测试先在旧行为上复现相同的 bluetoothMac 参数异常，再在修复后通过。
geely 的 8 项测试与 geely-core 的 2 项监听测试通过；根目录 AGENTS.md 规定的完整检查命令及认证版构建均成功。
APK 的包名、名称、签名、认证文件匹配和排除组件检查也需在交付时执行。

手机只进行了读取诊断，没有安装修复包、改变权限、清空应用或修改网络/蓝牙设置。
本次确认并修复的是认证前的确定性退出点；iPhone 是否接受后续识别、认证和画面/触摸/声音，仍需安装修复版后继续测试。
