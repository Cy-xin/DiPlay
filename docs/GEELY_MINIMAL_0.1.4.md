# 0.1.4：音频缓冲与帧率

基于 0.1.3 850b0a0f，包名 com.shihab.diplay，版本 104。

在连接选项中增加两个原生单选对话框，不新增页面或后台任务：

- 音频缓冲 100 / 150 / 200 / 300 / 500 / 1000ms，默认保持用户已接受的 200ms。低值可能断音，高值更稳但响应更慢；这是本地媒体播放缓冲，不是整条传输链路的实测延迟。导航与通话继续使用上游独立的低延迟通道。
- CarPlay 请求帧率 30 / 60，默认 30。原版 AirPlayDisplaySettings 将 maxFPS 限制在 30–60，未擅自放宽协议上限；界面注明 120 帧暂不支持。60 是请求上限，不保证 iPhone、Wi-Fi、解码器与屏幕持续达到60。

选择立即保存在原有私有配置中；下次连接生效，不自动中断会话。连接开始时冻结本次值，同时传入 AirPlay /info 声明及解码器运行速率；音频值直接传入成熟 AudioTrack 缓冲规划。连接、释放中禁用设置，并防止已打开的对话框在连接后修改配置。

操作：连接页 → 连接选项 → 音频缓冲或 CarPlay 帧率 → 选择 → 连接。已连接则先主动断开，再修改并连接。若有断音先试300或500ms；60帧卡顿先恢复30帧。

延续0.1.3自动布局。单测覆盖保存后重新打开、帧率实际协议声明、各缓冲值到规划的映射、越界值回退。安装与离线检查不能代替真实60帧、延迟与稳定性复测。
