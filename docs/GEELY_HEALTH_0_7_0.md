# DiPlay Geely 0.7.0：连接自检、运行指标与有限恢复

基线 `08508d8e`，独立分支 `codex/geely-connection-diagnostics`。只改最小应用层，继续复用旧版手动车机热点、蓝牙/iAP2、视频与音频实现；无新依赖。

## 操作

连接过程中或失败后，打开“诊断”：

- 连接自检：当前/中断阶段、已经过的阶段及具体排查提示。
- 运行指标：实际解码编码画布、收到/显示帧率、码率；各音频通道本机待播估算、累计欠载计数。请求的画布与 fps 另行标注，不冒充实测值。
- 最近连接的各阶段耗时和总耗时保留。
- 如有异常，填写问题说明并上传已有诊断日志，提供诊断编号。未经点击不上传。

指标来自原版解码器/播放器的约 5 秒统计回调，不新增采样线程或全局轮询。未知值显示等待/未知。静止画面收到帧率会变化，编码画布可能含旋转或裁切区域；音频欠载不等于用户听到的断音，本机待播估算不是 iPhone 到扬声器的完整延迟。没有音频统计时不会伪造零断音。

## 恢复策略

- 明确的网络变化、连接重置、broken pipe、网络就绪失败等才进入恢复。
- 控制通道使用旧版已输出的关闭原因辨别 I/O 异常；正常结束/主动断开不恢复。未能确认原因的断开保留手动重试，避免抢回用户主动结束的会话。
- 一个手动连接周期最多自动恢复两次，延迟分别为 2 秒和 5 秒；成功进入首帧不会重置预算，避免反复掉线形成无限循环。
- 先关闭旧连接、等待传输与媒体释放、归还进程租约，再安排恢复；释放失败禁止再次创建任务。
- 等待期间主按钮为取消。切换到后台取消尚未执行的重试；后台发生故障不启动新连接。原有正在运行的健康连接继续保留。
- 配置/认证/权限/配对失败不自动重试。手动点击连接才开始新的预算。不增加开机自启、后台轮询或系统网络设置自动化。

## 验证边界

需在吉利实车上验证：两种网络首次连接、音乐与导航、触摸、返回桌面保留、断网后恢复、恢复期间取消、长时间播放稳定性。编译、单元测试和模拟器页面不能替代上述实测。

## 离线验证结果

项目规定的检查与最小应用构建全部成功。geely 41 项、geely-core 53 项、shared 1654 项（含原有跳过）、common 1502 项，失败为零。新增测试覆盖有限恢复预算、永久错误排除、统计未知值/通道独立累计及恢复等待取消后不创建控制器。应用 lint、签名、包名、组件、R8 排除和本地认证资产一致性核验通过。模拟器大字号 1.3 下横屏 1280×720、竖屏 720×1280 截图检查通过（滚动内容）。
