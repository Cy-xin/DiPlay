# 吉利 OneOS 兼容包 · 更新说明

版本：`0.2.21-geely`（versionCode 44，包名 `io.dushu.car`）
日期：2026-11-06

本版本在原 DiPlay 之外新增一个**独立可选**的兼容构建，用于接入吉利 OneOS 车机的原车能力。普通 `com.shihab.diplay` 构建不受任何影响，两者可同时安装。

## 新增

### 在「应用建议」里直接打开 CarPlay

- 安装后即出现在主屏「应用建议」卡片中，**不需要先打开过应用**，原车按包名精确匹配入榜。
- 点击卡内图标即可进入 DiPlay 并连接 iPhone 开始投屏，图标由原车统一替换为 CarPlay 图标。
- 卡片上的播放键不再只是"打开应用"：它会直接开始播放，且**不再出现画面跳到应用界面再退回的闪烁**。

### 播放音乐同步仪表盘

- 播放时仪表盘音乐页同步显示当前曲目、歌手与播放进度；主屏媒体卡与仪表盘使用同一份上报数据。
- 原车约每 0.7 秒查询一次播放进度，应用持续应答；超过约 4 秒无应答会被判为离线，因此心跳是必需项，不是优化项。
- 暂停/播放状态与卡片、仪表盘三处保持一致。

### 原车媒体卡控制

- 支持播放、暂停、上一曲、下一曲；卡片上的播放键（原车以启动跳板的方式下发）与暂停键（广播）分别处理。
- 方向盘媒体键独立分组，避免与原车媒体键同组导致 120 毫秒去重失效而重复下发。

## 修复

- **从媒体卡按播放键时画面跳走再跳回**：原因是跳板把应用主界面拉到了前台。现在只有"当前没有可播放的会话"时才会打开应用窗口，其余情况只发播放请求，且跳板独占任务栈，结束后不会把应用带回前台。
- 兼容构建的包名不再带 `.hudtest` 后缀——后缀会导致原车名单匹配失败，得到一个装了也没用的包。

### 仪表专辑封面（2026-11-06）

- 修复封面已到达 DiPlay、仪表仍显示默认音乐图标的问题。原车专用媒体广播此前把 `RECEIVER_MEDIA_BOOK_COVERURL` 固定为空；仅发布 Android MediaSession 图片不会自动填充原车的 `musicPic`。
- 用私有 FileProvider URI 同时上报封面，并给原车媒体读取组件授予只读权限。实际抓到 `com.geely.mediawidget` 读图权限拒绝后，补全其授权；不开放整个应用目录。
- 图片异步到达时立即更新原车卡片，保持音源所有权检查；换歌后保留旧图片至少两分钟，供原车异步读取。
- 此车实测：用户确认仪表右侧专辑封面出现；收尾版本原车服务收到非空封面 URI，后续观察未见读图权限拒绝。尚不代表其他车型均兼容。

### 侧边栏可编辑快捷应用（2026-11-06）

- 兼容构建的最终应用关闭 `debuggable`，保持 `io.dushu.car` 和既有签名，版本号升级到 44。普通调试包仍保留调试能力。
- 原车 `kx11a2_edit_app_list` 包含 `io.dushu.car`，但侧边栏编辑器会过滤 `FLAG_DEBUGGABLE` 应用。仅改变名称或图标不能解决缺席候选列表的问题。
- 此车实测：覆盖安装后 DiPlay 出现在候选菜单；拖到最后一个快捷位并返回桌面后保留，点击可进入已连接的 CarPlay。

## 已知限制

- 卡片不响应收藏指令，不伪造收藏状态。
- 书 ID 与播放位置原车会回显本应用上报的值，不是 iPhone 曲库标识，因此不据此 seek。

## 安装

```bash
adb install -r DiPlay-geely-compat-debug.apk
```

- 包名 `io.dushu.car`，需与车上旧版本签名一致才能覆盖安装（当前为同一 debug 签名）。
- 已内置 CarPlay 配件认证资产（`assets/offline-mfi/`），无需额外配置。
- 构建与校验方式见 `GEELY_OEM_COMPATIBILITY_BUILD.md`；产物校验脚本 `scripts/verify_compat_apk.sh`。
