## 任务 02：自适应

代码事实：ReceiverApp 对 KX11 的 LocalDensity 乘以 1.35，fontScale 保留系统值。本次不叠加缩放。历史 0.9.5 实车报告观察到 Surface 为 1920×720；报告没有记录实际系统 density/fontScale/insets，不能反推完整可用 dp，也不能把离线配置称为当前实车设置。

验证配置：420×900、1280×720，mdpi，系统字号 1.0/1.5，深浅色，四种连接状态；附加 1920×720/KX11（有效 density=1.35，字号1.5）、720×420短横屏、RTL。可用区域仍由 safeDrawingPadding/imePadding 扣除系统边距，运行时测量后布局，不锁定固定分辨率。车机字号1.5测试的文字物理比例为 1.35×1.5，不再次人为放大。

- 字号按 hero/title/section/body/label/secondary/caption/meta 收拢到 ReceiverTokens，按钮使用 touch=48dp、controlMin=56dp；标题、正文和辅助文字层级保留。
- 竖屏或短屏隐藏原有装饰口号，其余场景保留原意。配置内容可滚动；主按钮在内容滚动区域外，横屏靠左、竖屏全宽。
- 状态使用文字和线性图标；连接中的无限进度动画改为静态等待图标，避免为等待持续绘制。Robolectric 原生渲染中也观察到无限进度动画使调度持续运行，未将其当作实车卡顿根因。
- 长状态完整文本放入有界滚动区域，预览最大64dp，展开最大120dp；不再省略尾部。“重试连接”复用原主按钮，不创建第二条连接路径。首次连接按钮仍为“连接 CarPlay”；连接中是“取消连接”；已连接是“返回 CarPlay”。
- 连接模式选中标记与展开图标改为 Canvas 路径，装饰图标不重复朗读；模式和分类保留 selected/role 语义。

## 任务 01：静态玻璃绘制

修改前的代码事实：API30 不执行 .blur，API31+ 才模糊；CarPlay 正常画面已绕过 ReceiverScene 和所有装饰面板。本次保留该绕过，不把模糊当作本车地图卡顿的已知原因。

移除每个 GlassSurface 中重复 drawScene、onGloballyPositioned、Backdrop/LocalBackdrop 及偏移对齐状态。每个页面或独立弹窗仍由 ReceiverScene 绘制一次静态背景；GlassSurface 签名与调用方式保持，改为主题半透明填充、细高光边、4dp轻阴影。

视觉差异：冷灰蓝品牌色不变，面板比旧版更均匀，减少面板内重复的波纹与亮斑；浅色填充 alpha=.76、深色=.86，优先保证文字清楚。API31+ 也不再重画并模糊静态场景。不新增运行时模糊库，没有 GPU 测量，不报告实际帧率/耗电改善幅度。

对比度检查使用真正渲染的玻璃空面板图：API30、1280×720、完整场景与面板最终合成像素，内缩40px、每4px采样，按 WCAG sRGB 线性化亮度计算 onSurfaceVariant（浅 #4B596C、深 #B8C6DA）；结果见本次检查产物。不是仅将 token 色值相互比较，不保证未经测试的外部背景或主题过渡每一瞬间。正常文字另有更高对比度的 onSurface。
