# DiPlay Geely 0.1.3：屏幕适配与音频延迟试调

基于用户已确认画面、触摸、音频工作的 0.1.2（f64f91294da400da71bff14d1e0f47d53f418db4），分支 codex/geely-latency-ui。包名 com.shihab.diplay，versionCode 103。

## 本次改动

- 连接页按实际可用窗口 dp 和字体倍率自动在左右分栏、上下布局间切换，无需用户填写分辨率。
- 主操作和连接状态固定底部；紧凑布局的模式与配置在独立区域滚动，大字体不靠缩小文字硬塞。
- 窗口密度变化交给系统重建 UI；连接参数继续保留。改变实际视频区域时仍结束旧会话并提示重连，避免触摸坐标与分辨率错位；不引入自动重连循环。
- CarPlay 申请分辨率来自实际视频区域，取偶数尺寸，不再分别强制最小 640×360 造成比例偏差。未完成布局时不会创建连接任务。
- 纯本地原生界面，统一色彩，收起接口与已配对设备选择；未增加框架、后台组件、连接模式或扩展功能。
- 媒体起播缓冲由 300ms 试降至 200ms，保留成熟的额外容量与重缓冲逻辑。电话、Siri、导航的原有低延迟通道逻辑未改。

## 证据及限制

0.1.2 的手机日志显示音乐为类型 102（AAC LC、48kHz），AudioTrack 起播阈值 300ms，容量 500ms；存在较大网络到包间隔。0.1.3 的目标阈值为 200ms、计划容量 400ms，系统最小缓冲可使实际值更大。这些数值不是端到端延迟，不能直接相加；也不代表实测已减少 100ms。

没有修改 iPhone 的音频时间戳、反馈时钟或认证协议。没有以关闭 103 buffered stream 宣称优化，因为实际记录中不是该通道。若出现卡顿，应对比保留的 0.1.2；未加入高级音频调节页面。

自动布局回归覆盖 1280×600、1024×480、640×360、480×600，字体 1.0 / 1.35，检查主按钮与状态边界。另有模拟车机实际截图。模拟器和布局单测不能代替吉利实车、不同 OEM 字体和端到端音频测试。

## 最短操作

热点：开启原车热点 → iPhone 加入 → 保持蓝牙配对 → 填热点名称和密码，连接选项中核对接口（默认 wlan0）→ 连接 CarPlay。

局域网：车机和 iPhone 加入同一可互通 Wi-Fi → 保持蓝牙配对 → 选择同一局域网并填写网络名称和密码 → 连接。发现失败检查客户端隔离和组播。

允许麦克风权限以完成音频能力协商；仅在 iPhone 请求输入通道时采集，不保存录音。保留原版基础重连能力，不增加后台轮询。

## 复测清单

1. 两种模式分别连接，画面填满可用区域，触摸位置准确。
2. 播放后暂停、切歌，对比 0.1.2 主观延迟和连续播放断音。
3. 导航播报及音画同步；手机与吉利车机分别验证。
4. 大字体、小窗口首次打开，滚动配置后状态和连接按钮可见。
5. 断开、取消、失败重试；已连接时仅显示画面与断开入口。
