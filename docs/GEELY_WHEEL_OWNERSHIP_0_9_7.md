# 0.9.7：播放／暂停键前台接管

基线 a61734fe，继续 codex/geely-return-picture。

## 问题与实现

现有代码对吉利按键服务仅调用 registerListener，收到 200085 后向 CarPlay 转发。监听不等于消费按键，原车播放器仍可能同时处理，从而唤起原车音频。此为代码层面的风险定位，尚无本次实车复现证据。

复用仓库已存在、按原车 Binder 顺序定义的 IInputManager.interceptKeyCode/releaseKeyCode，不新增服务、权限、轮询、白名单或包名变更。

- 只接管实体播放／暂停键 200085。必须 CarPlay 已出首帧、CarPlay 页面显示、Activity 已恢复到前台、无断开释放、无按键检测。
- 接管返回 true 才向 CarPlay 转发这个键。拒绝或异常时停止重复转发，日志保留请求与实际返回值，并在方向盘设置提示使用屏幕控制。不能据此承诺原车停止响应。
- 返回 DiPlay、离开应用、暂停、断开、关闭监听或开始实体检测时释放。映射设为“不执行 CarPlay 操作”时也释放。
- 返回前台 CarPlay 可再次接管；重复布局和状态刷新不反复接管已持有的键。
- 后台这个实体键交还原车，DiPlay 不再同时向 CarPlay 转发。下一首、上一首、MODE 长按 Siri、语音键和音量键保持现有逻辑。
- 实体检测仍是被动监听，不调用接管接口；屏幕上的控制测试仍走原有 CarPlay 控制通道。
- 只释放本实例记录为接管成功的 200085；释放失败不会伪记成功，保留 owned 状态与日志供后续状态更新再次释放。关闭时尝试释放后解绑，不保证系统服务故障时可恢复，需实车检查。

## 验收

自动检查覆盖：默认被动不接管、前台成功后只转发一次、重复状态不重复接管、返回/暂停释放、关闭前释放、禁用映射释放、接管拒绝不重复转发、其他键不受影响、断开后取消队列事件、检测保持被动。

实车必测：
1. 原车播放器关闭，连接 CarPlay 并播放音乐，短按 200085 暂停/恢复，确认原车音乐不启动且每次只切换一次。
2. CarPlay 音乐暂停时再按，确认只恢复 iPhone 音乐。
3. 返回 DiPlay、车机主页和断开后，原车按键恢复。
4. 查看日志 play_pause_takeover 的 accepted/owned；若拒绝或原车仍响应，不把本包视为已解决，后续需连接车机检查厂商服务行为。

不替换、停用原车应用；不修改系统文件，不申请 Root/系统签名。
