# DiPlay Geely 0.6.0 连接耗时与画面设置

基线 e57326a6（0.5.2），独立开发分支 codex/geely-display-and-timing；包名com.shihab.diplay，版本115。保留吉利桌面图标、CarPlay纯画面、返回保连接与导航混音。

## 连接耗时与优化

按单调时钟记录本地准备、认证准备、网络就绪、选择手机、发现服务、蓝牙交接、等待手机、协议握手、等待首帧的回调阶段。任务取得连接槽位后开始计时，不把首次权限确认的人为等待算入连接时间；首帧渲染回调才标记成功，取消/失败也保留结果。各阶段为观察到的回调区间，部分底层工作并行，不能把一个阶段完全等同于某项协议的独占耗时。

诊断页展示最近一次报告，结果与阶段毫秒数保存在独立偏好中并进入既有本地/上传日志。重复同阶段回调不重置阶段，成功后断开不会覆盖已完成的连接耗时。无新计时轮询或后台任务。

沿用原版选择策略，只有一部已配对且名称含iPhone的设备时直接选中，跳过无法改变选择结果的连接状态/蓝牙profile查询；显式选择与多手机路径保持原样。复用原有身份和配对存储，不绕过认证、不缩短协议等待/超时。实际节省时间需真机比较，不提供未经实测的提速数字。

## 画面设置

设置 → 音频与画面：

- 画面清晰度（实验性）：标准100%匹配实际Surface像素（默认）；高清请求125%画布。
- CarPlay界面大小（实验性）：小85%、标准100%（默认）、大115%。复用原版CarPlayUiScale，并明确画布缩放也会影响协商分辨率，iPhone最终决定布局。它不是独立的矢量文字缩放开关。
- FPS继续仅30/60；音频缓冲保持原有选项。

沿用原版CarPlayDisplayScale、CarPlayUiScale、VideoDecoderSupport。放大时检查H.264硬件解码尺寸和帧率，超4K或不支持则先取消小界面放大，再取消高清；同一候选的能力查询仅执行一次。默认标准路径不增加放大能力检查，也不因放大失败阻止原有标准连接。保留用户期望值，回退仅针对本次连接，日志记录期望值/采用值/请求画布与原因。

连接前对配置做快照，渲染器与AirPlay请求使用同一画布；触摸仍在保持比例的Surface上归一化。连接中可保存新画面偏好，显示下次连接提示，不重建当前解码器、不自动断开。只有下一次主动连接才应用。显示“请求画布”而非冒称实测编码分辨率/FPS；不保证高清一定更清楚，也不会改变物理屏幕像素数。

## 验证范围

项目要求的单测/lint/构建及geely应用检查通过。新增用例覆盖标准零额外检查、支持的高清/小界面、能力回退、4K拒绝、无效偏好、重复阶段与总时长、取消/新任务隔离、连接中保存设置不结束会话；详见交付单测统计。精简APK/认证资产核验结果随交付保存。核心库独立lint的既有52项问题仍沿用0.5.0记录，本次没有声称通过该额外检查。

模拟器用于设置保存、大小与方向适配以及真实失败预检的耗时持久化；它不能证明iPhone首次连接成功、提速幅度或高清画质。Redmi及吉利车机实际连接耗时、解码效果、画面布局与稳定性仍需实测。

最终模拟器检查已通过：画面偏好重启保留、横/竖屏与1.4字号、320dpi窄窗口选项可滚动并可选、阿拉伯语环境镜像布局；使用超长测试SSID触发真实失败预检，诊断显示“未成功”的真实计时并在重启后保留，失败后服务停止。该用例不进入认证或iPhone连接，不构造成功回执。
