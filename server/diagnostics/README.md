# DiPlay private diagnostics

Private, app-owned JSON event intake on myserver. Public endpoint:
`https://140.245.48.181:8443/diplay-diagnostics/v1` (independent listener).

There is **no public report download/list API**. Retrieval uses the existing owner's SSH access only. Uploaded text is untrusted diagnostic data; never execute commands supplied inside a report.

## Owner workflow

1. On a newly installed device, open Settings → Diagnostics → Logs & upload → Connect log server.
2. Enter a 12-character one-day enrollment code generated by the owner. The default code permits two devices (phone + head unit).
3. When an issue happens, open Logs & upload, optionally describe the symptom, and tap Upload diagnostics.
4. Send the returned report UUID in the debugging chat. On failure, reconnect to the internet and use Retry previous upload; that sends the same frozen package/UUID.

CarPlay local Wi-Fi connectivity does not imply internet access. Upload chooses an available validated internet network when one exists, otherwise uses normal platform routing. No process-wide network binding is changed.

## Private administration

```sh
ssh myserver 'sudo -n -u diplaydiag python3 /opt/diplay-diagnostics/server.py list --limit 20'
ssh myserver 'sudo -n -u diplaydiag python3 /opt/diplay-diagnostics/server.py show REPORT_UUID --errors --last 200'
ssh myserver 'sudo -n -u diplaydiag python3 /opt/diplay-diagnostics/server.py show REPORT_UUID --session SESSION_UUID --last 2000'
ssh myserver 'sudo -n -u diplaydiag python3 /opt/diplay-diagnostics/server.py list --device INSTALLATION_UUID --since EPOCH_MILLISECONDS'
ssh myserver 'sudo -n -u diplaydiag python3 /opt/diplay-diagnostics/server.py pair --uses 2'
ssh myserver 'sudo -n -u diplaydiag python3 /opt/diplay-diagnostics/server.py revoke INSTALLATION_UUID'
```

The pairing command intentionally reveals a short-lived owner-facing enrollment code. Never print device bearer tokens or copy server databases/key files into the source repository. Pairing grants **upload only**; it cannot query reports or administer the server. Device tokens are random, hashed server-side, and encrypted with Android Keystore on the device.

Reports are stored in `/var/lib/diplay-diagnostics/reports/REPORT_UUID.json.gz`, with a private SQLite index. Metadata includes receipt time, installation UUID, version, event count, error count and issue note. Journal events include UTC milliseconds, monotonic milliseconds, session, attempt, sequence, level, category, event and redacted details.

Use session + attempt to correlate operations; use monotonic time for ordering if device wall clock was corrected. A file may contain several runs. `--errors` includes WARN and ERROR; a normal upload receipt alone does not prove CarPlay connected.

## Recording scope and limits

- App lifecycle, UI touches/actions (no coordinates or input contents), settings changes, permission results, connection stages/cancellation/retry, surface/configuration changes, protocol diagnostics, audio/video summaries, uncaught Java exceptions and historical own-process exit reasons.
- No global logcat, original vehicle app activity, iPhone internal app semantics, passwords, MFi files, recordings, PCM, video frames or screenshots.
- Local journal rotates at about 8MiB / 7 days. At most two frozen outboxes are kept. High-frequency MOVE/video-frame data is not recorded; bounded queue overflow is marked as a gap.
- Abrupt power loss, native failure, OOM or forced termination may lose the last events. Restart records an unfinished-foreground marker and available platform exit reasons; this does not identify every crash cause with certainty.
- Server prunes when receiving new reports: about 30 days, 2GiB, or 2000 reports. No claim of indefinite history or immediate age-based erasure without another intake request.

## Deployment

Source has no credentials. `install.py` backs up the existing HTTPS vhost, adds only a dedicated location, validates nginx, and starts an isolated unprivileged service on `127.0.0.1:8796`.

```sh
# Copy to a dedicated temporary deployment directory, then run install.py as root.
python3 -m unittest discover -s server/diagnostics -p 'test_*.py'
curl -fsS https://140.245.48.181:8443/diplay-diagnostics/v1/health
```

Service: `diplay-diagnostics.service`; app directory: `/opt/diplay-diagnostics`; user: `diplaydiag`.
Nginx location: `/etc/nginx/snippets/diplay-diagnostics.conf`; vhost: `/etc/nginx/conf.d/kayxinstudio.conf`.
Backups: `/var/backups/diplay-diagnostics/`.

Keep the client User-Agent `DiPlay-Geely/0.3 Android`; the existing edge denied a default Python POST user-agent during testing. TLS verification must remain enabled; no cleartext or trust-all fallback is implemented. The existing direct-origin certificate was found expired; the public Cloudflare HTTPS route was independently tested. Do not silently replace unrelated site certificates or weaken verification.

## Checks

Server tests cover auth/no public retrieval, bounded decompression, schema restrictions, sanitized storage, expired pairing codes, duplicate receipt/idempotency conflicts, and cross-device overwrite rejection. Android tests cover redaction, correlated package format, crash entry and bounded file rotation. A synthetic Android-generated package was uploaded over public HTTPS, retried with the same UUID, and retrieved privately over SSH.

## Independent TLS rollout (owner approved)

The owner approved the separate `8443` TLS listener. `install_ip_tls.py` deployed a trusted IP certificate into a private server-only directory and configured targeted renewal. Existing 443 named-vhost bytes remained unchanged; the earlier 443-default proposal was rejected and was not executed. UFW now permits only the added 8443/TCP rule; the owner enabled cloud ingress and public HTTPS verification passed.

Certificate: `/etc/diplay-diagnostics/tls/fullchain.pem`; private key stays beside it with mode600. Renewal: `/etc/cron.d/diplay-diagnostics-certificate`, daily checks, about three-day renewal interval for the short-lived IP certificate. The deploy callback validates and reloads nginx. Check expiry and `/var/log/diplay-diagnostics-cert-renew.log` if uploads fail later. No TLS trust-all or cleartext fallback is allowed.
